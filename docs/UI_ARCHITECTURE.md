# Stardia v0.0.7.1 UI構成と画面状態

## 責務

- `index.html`: 共通ヘッダー、左ナビ、7画面、4編集ダイアログ、表示設定ダイアログ。
- `app.js`: Repositoryとの接続、画面切替、フォーム、保存状態、フォーカス、入力破棄確認。
- `ui/views.js`: ダッシュボード、計画・項目・記録・分析の描画。HTML文字列は既存escでエスケープ。
- `ui/view-state.js`: 画面一覧、タブ内閲覧状態の検証、期間計算、25件ページ分割。
- `ui/ai.js`: 専用画面の出力・入力、差分テーブル。domain/aiの検証・更新形式は変更しない。
- `ui/backup.js`: データ管理の出力・確認・復元。保存transactionは変更しない。

7画面は同じHTMLに置き、非選択画面はhiddenで操作対象から外す。AI・復元のファイル入力や確認途中のDOMは画面切替で再生成しない。単一プロジェクトUI、保存層のprojectIdと将来の複数プロジェクトへの分離は維持する。

## ナビゲーション

`?view=today|plans|items|records|analysis|ai|data`。未知値はtoday扱い。デモは既存の`#demo`を維持。ルートURLは現在のpathnameを使い、GitHub Pagesのサブパスで動く。ナビ定義はview-state.jsのviews。

クリック時にpushState、popstate時に表示変更。history.state内のstardiaIndexで未保存入力を破棄しない「戻る」を元の履歴位置へ戻す。再読み込み時も既存のindexを引き継ぐ。履歴で実データ／デモのハッシュが変わる場合はRepositoryを切り替え、実データとデモを混在させない。

画面移動時は見出しへフォーカスし、先頭へスクロールする。検索条件は各画面の最新状態を保持する方式で、履歴の各エントリごとに過去のフィルター状態を再現する方式ではない。

## 閲覧状態と保存互換性

sessionStorage `stardia.ui.session.v1` に plans/items/records/analysis の条件とページ番号、settingsOpenを保存。壊れた値、未知のenum、無効な日付は標準値に戻す。sessionStorage利用不可時はメモリ内で操作できるが、再読み込み時の閲覧状態保持はできない。

これは学習データでなくタブ単位の閲覧状態。完全バックアップには含めない。テーマ・アクセント・カード表示の既存preferencesはIndexedDBが正であり、そのまま復元する。カード非表示設定を再設計でリセットしない。

DB version 3 / snapshot schemaVersion 2 / stardia_backup schemaVersion 2 / AI JSON schemaVersion 1のまま。保存層と既存コマンドは維持し、domain/commands.jsへrestoreItem・restoreScheduleだけを追加する。旧データの新規移行は発生しない。

## 表示と件数制限

今日のカードは常に実際の当日。別日の確認・編集は学習計画で行う。今日の予定10件、最近の実績5件、概要の時間内訳3件。すべてのデータは詳細画面から参照でき、保存内容を切り捨てない。

計画・項目・記録・分析内訳は25件ずつ。検索・日付条件の変更で先頭ページへ戻る。削除などでページが範囲外になったら有効範囲へ補正する。現段階は全データをメモリ内で抽出してから表示件数を制限し、DBカーソルによる逐次読込・仮想スクロールは実装していない。

計画は日次、週次（月〜日）、任意期間、全期間。実績は開始／終了日を片方だけ指定することも可能。分析は今週、今月、全期間、任意期間で、対象実績のsubject文字列を既存summarizeで集計する。学習項目別の正規化・分類別集計には変更していない。

## 編集・入力・フォーカス

既存の編集フォームとコマンドを再利用。予定からの記録は日付・項目・予定・時間を事前入力。学習した実績と予定の完了は別概念のまま、既存の「保存と同時に完了」チェックを維持する。

保存中は関連する操作をロック。失敗・競合時はフォームを開いたまま入力とエラーを保持する。保存成功で操作元へフォーカスを戻す。対象がアーカイブ等で消えた場合や別画面に移動した場合は見出しを代替先にする。

閉じる・Escape・履歴移動では、フォームの初期値と現在値を比較して変更があれば破棄確認。再読み込み・ページ離脱はbeforeunloadで確認を要求する。ブラウザの終了方法・OSによって離脱確認が出ないこともあるため、下書きを永続保存する機能ではない。

AIの貼付・選択ファイルは画面移動で保持。内容を編集したら以前の確認を無効化。デモ切替時は確認のうえ入力を破棄する。AIプレビュー後も、適用時のrevision/digest再検証と原子的保存は従来どおり。

## AI差分

操作名は日本語、追加／変更／アーカイブは見出しと色で区別。変更フィールドだけを前後比較し、日付・実績の内容は変更がなくても文脈として表示。変更箇所は文字でも「変更」と表示し、色だけに依存しない。

保持する実績件数は概要に表示。対象ID・JSON全文・関連IDはdetails内。項目参照は名称、予定参照は日付で表示する。文字列はtextContentで表示。プレビュー成功後は入力欄を折りたたみ、プレビューへフォーカス・スクロールする。警告と最終確認チェックは残し、即時適用しない。

## 後続拡張と制約

ヘッダーのプロジェクト入口、項目の一覧、計画・実績の絞り込み、分析画面を将来の拡張点とする。自由分類・階層・テンプレート・複数プロジェクトのデータモデルは今回追加しない。同期なし。

PCを優先し、390pxでは横スクロール可能なナビと縦積み表示で操作を維持する。スマホ専用ナビ、実機Safari/Firefox、スクリーンリーダーによる網羅検証、巨大データの性能計測は後続対応。

## v0.0.7の復帰とアクセシビリティ

restoreItemは対象のarchivedだけをfalseにする。関連予定の自動復帰は行わない。restoreScheduleは項目が有効な場合だけ許可し、対象のarchivedだけをfalseにする。有効済み・未知ID・古いrevisionを拒否。いずれも既存Repository.mutateによる原子的保存で、記録と参照を変更しない。AI更新JSONへ新しい操作は追加していない。

plans.stateにactive/archivedを追加。旧sessionStorageではactiveを補完する。アーカイブ予定にも期間検索が適用されることを説明し、項目が未復帰の予定は復帰ボタンの代わりに前提条件を表示する。

同じレコードのボタンが複数画面にあるため、フォーカス復帰は表示中・有効な要素に限定する。復帰で行が消えた場合は次の復帰ボタンまたは画面見出しへ移動。非表示カードの再表示は設定ダイアログ内でなく、再表示したカードへフォーカスする。保存エラーは入力を維持しエラーメッセージへ移動。

検索・ページ移動の件数を単独のpolite live regionで通知し、一覧全体の再読上げを避ける。保存中はmainへaria-busyを設定。アーカイブはテキストでも区別し、配色だけに依存しない。ナビの選択文字色はテーマの本文色、フォーカス枠もテーマごとに設定する。

## v0.0.7.1 登録入口の整理（再設計の段階1）

学習計画のplan-entryを計画作成の入口とする。ここを後続の計画エディタへ拡張する。
新しい内容は既存itemフォーム→保存成功→既存taskフォームの順。初回テーマは既存project.nameへ保存し、作成成功後に学習計画へ移動。description/goal/期間は初回だけ折りたたむ。編集時は開いて表示する。
今日は実行・チェック・詳細記録。項目追加のヘッダーボタンは学習項目画面だけ。学習項目の計画へのショートカットは、学習計画へ移動して同じtaskフォームを開く。

新しい内容を保存する段階と予定を保存する段階は、各々独立した既存トランザクション。
UIで「内容を保存して日付へ」と説明し、予定をキャンセルしても保存済み内容を削除しない。
その状態は登録済みの内容から再開可能。未保存項目のキャンセルは既存の入力破棄確認を使用する。
失敗・競合時は元フォームを維持して次へ進めない。最新内容の明示確認後に再保存する。
成功後のフォーム切替はdialogのcloseイベント後に行い、閉じる処理による編集状態の混線を避ける。
次フォームから閉じたときの復帰先は学習計画内の「登録済みの内容を使う」。
予定保存後は有効状態・その日付へ絞り込みを合わせ、作成結果を見失わないようにする。

domain・storage・AI JSON・完全バックアップの実装はv0.0.7から変更しない。
この段階は新しい具体化状態や階層を実データへ保存しない。将来仕様はplanning/REDESIGN_DECISIONS.mdで区別する。

段階1の表示版名はv0.0.7.1。package.jsonはSemVer互換の0.0.7+flow.1とする（公開パッケージではない）。
