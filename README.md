# Stardia（スターディア）v0.0.7.1

小さな学びを、未来につなぐ。ログイン不要の学習管理Webアプリ開発版です。

## 起動

このリポジトリで次を実行します（Python 3）。

```powershell
python -B -m http.server 8765 --bind 127.0.0.1 --directory dist
```

http://127.0.0.1:8765/ を開きます。終了はCtrl+C。Pythonは静的ファイル配信のみで、保存APIはありません。HTMLのダブルクリックではなくHTTPで開いてください。

**毎回同じホスト名・ポートで起動してください。** localhostと127.0.0.1、異なるポート・プロトコルは別の保存領域になります。

## 画面構成（v0.0.7.1）

左ナビの7画面を、同じ静的Webアプリ内で切り替えます。

| 画面 | 主な操作 |
|---|---|
| 今日 | 今日の予定・必須完了数・予定時間／実績時間、完了チェック、予定からの実績入力、今週の概要、直近5件 |
| 学習計画 | 日次／週次／任意期間／全期間、項目名検索、追加・編集・アーカイブ・復帰 |
| 学習項目 | 名称検索、有効／アーカイブ切替、予定数、追加・編集・復帰・予定への割当 |
| 学習記録 | 日付・期間・項目・内容の絞り込み、実績追加・編集・削除 |
| 分析 | 今週／今月／全期間／任意期間。実績の「学習した内容」文字列別の時間集計 |
| AI連携 | 相談用出力と更新取込。日本語の前後比較、変更フィールド強調、JSON詳細の折りたたみ |
| データ管理 | 完全バックアップ・復元、保存先・定期バックアップの案内 |

プロジェクト設定はヘッダーのプロジェクト名から開きます。テーマ・色・カード表示は「表示設定」のパネルで変更できます。設定パネルは初期状態で閉じています。管理一覧・集計内訳は25件ずつ、今日の予定は最大10件を表示し、残りは学習計画で確認できます。

URLの`?view=plans`などで画面を指定でき、戻る・進むにも対応します。検索条件・表示日・ページ位置・設定パネルの開閉は同じタブのsessionStorageへ保存し、再読み込みで引き継ぎます。これらは一時的な閲覧状態で、学習データや完全バックアップには含めません。テーマ・アクセント・カード表示は従来どおりIndexedDB保存と完全復元の対象です。

未保存フォームを閉じる場合や戻る操作で離れる場合は破棄確認を出します。AI入力は画面移動で維持し、再読み込み・タブを閉じる際はブラウザの離脱確認を要求します。下書き自体の永続保存はありません。フォーム保存後は操作元、対象が消えた場合は画面見出しへフォーカスを戻します。

詳細は [UI設計](docs/UI_ARCHITECTURE.md) と [再設計の確定方針](docs/planning/REDESIGN_DECISIONS.md)。保存スキーマ・DBバージョン・AI JSON・完全バックアップの形式はv0.0.5から変更していません。

## v0.0.7の操作改善

- 予定行は「実績を記録」を優先。予定時間と実績時間、完了状態を分けて表示します。
- 学習計画の「状態 → アーカイブ済み」で過去の予定を確認・復帰できます。日付で見つからない場合は「全期間」を選びます。
- 学習項目も「アーカイブ済み → 項目を復帰」で戻せます。関連する予定は自動復帰しません。項目を戻した後、必要な予定だけを個別に復帰してください。
- 復帰はID・日付・時間・完了状態・過去の実績を維持します。新たな確認ダイアログは設けず、既存のアーカイブ確認、データ削除・完全復元・AI適用確認は維持します。
- 検索結果の件数と表示範囲、操作対象付きボタン名、フォームラベル、キーボードフォーカスを改善しました。保存エラーは入力を保持してエラー箇所へフォーカスします。
- AI差分は項目名・日付・アーカイブを明示し、IDとJSON全文は展開して確認できます。

## 自分の学習とデモ

初回は空の学習環境です。GUIだけで次の順に始められます。

1. 今日の「学習テーマを決めて始める」でテーマを入力。目標・期間は任意で、折りたたみから設定できます。
2. 保存すると「学習計画」へ移動。「新しい内容から予定を作る」を選びます。
3. 学習内容を入力し「内容を保存して日付へ」。同じ画面の次のフォームで日付・予定時間を設定します。
4. 今日の画面で予定をチェック。時間・メモを残す場合は予定行の「実績を記録」を使います。
5. 同じ内容を再利用するときは学習計画の「登録済みの内容を使う」。名称・説明・アーカイブは学習項目画面で管理します。

日付設定を途中で閉じても、直前に保存した学習内容は残ります。再読み込み後も「登録済みの内容を使う」から再開でき、内容を再登録する必要はありません。保存失敗・競合時は入力を残して、その段階に留まります。

今日の画面から項目・予定を直接追加する入口を取り除き、「計画を作る・見直す」へまとめました。初回案内があるときは案内内のボタンを使用します。「予定外の学習を記録」と予定行からの実績入力は維持します。学習項目の「計画で使う」も学習計画へ移動して同じ予定フォームを開きます。

**v0.0.7.1は再設計の段階1です。** 階層・テンプレート・繰り返し・具体化の自動判定はまだ実装していません。予定時間と詳細実績の時間は現行どおり必須です。チェック自体は時間入力なしで保存できますが、実施日付きの完了履歴は後続段階で対応します。

項目・予定・記録はそれぞれ独立したIDを持ちます。項目を改名すると予定の表示名も変わりますが、過去の記録に入力した内容・日付・時間は変わりません。実績が関連する予定を別項目へ付け替える操作は拒否します。その場合は新しい予定を作ってください。

学習項目のアーカイブは項目と関連予定を一覧から外す処理、予定のアーカイブはその予定だけを外す処理です。参照情報と過去の実績は保持し、バックアップにも含めます。アーカイブ済み項目は学習項目画面の「アーカイブ済み」で確認・復帰できます。プロジェクト削除は、確認のうえ関連する全データと移行前の退避データを削除します。

実データはIndexedDB `stardia.learning.v1` に保存し、再読み込み・ブラウザ終了後も同じブラウザとオリジンで利用できます。既存データを初期化やデモで上書きしません。

「デモを試す」は架空データ専用のメモリストアに切り替えます。URL末尾の `#demo` でも開けます。デモの追加・編集・削除は実データに影響せず、再読み込みでリセットされます。表示設定は実データ・デモで共通のIndexedDB管理です。旧版のlocalStorage設定 `stardia.ui.v1` は最初の起動時だけ引き継ぎ、以降はIndexedDBを正とします。

## AIとのJSON連携

「AI連携」で、指定日・期間・週・プロジェクト全体の相談用JSONを出力できます。学習内容・メモを含むため、AIへ渡す前に内容を確認してください。APIへの直接接続はありません。デモでは利用できません。

1. 対象・期間を指定して相談用JSONをダウンロード。
2. JSON内の指示テンプレートとともにAIへ相談し、更新JSONを生成。
3. ファイル選択または貼り付けで読み込み、「変更をプレビュー」。
4. 件数・日付・項目・変更前後・削除・警告を確認してチェックし、一括適用。
5. 再読み込み後も保持。通常の完全バックアップに更新結果を含められます。

実績の追加・明示更新、予定の追加・変更・削除を最大500操作／2MiBで扱います。予定変更で過去の実績を変えません。同一対象の重複操作、古いコンテキスト、同内容の重複追加、別タブとの競合は拒否し、全件成功または全件取り消しにします。実績の追加だけでは予定を完了にしません。完了切替はダッシュボードで行います。

相談用JSONは完全バックアップではありません。古い更新が拒否されたら照合値だけを書き換えず、最新コンテキストを出し直してください。正式仕様・操作一覧・架空サンプルは [AI_JSON.md](docs/AI_JSON.md)。v0.0.4のDB・バックアップ形式は変更していません。

## 保存の安全性

- 保存成功はIndexedDBトランザクション完了後に表示します。
- 更新失敗時は成功表示にせず、フォーム入力を残します。チェック操作は保存前の状態へ戻します。
- 同じプロジェクトの更新にはrevisionを必須とし、別タブの更新と競合したら拒否します。自動マージ・自動再送はしません。
- 競合時は編集画面の「入力を残して最新データを確認」で最新の保存内容を表示し、入力と比較してから保存してください。
- 開けないDB、未対応の形式、初期作成失敗でデータを消去したり、メモリ保存へ黙って切り替えたりしません。

## 完全バックアップ・復元

実データの画面で左ナビの「データ管理」を開きます。

1. 「完全バックアップをダウンロード」でJSONを保存します。すべての保存済みプロジェクト・計画・記録・進捗・表示設定を含み、デモの学習内容は含みません。
2. 復元は「復元するJSON」でファイルを選び、作成日時・件数・名前・現在のデータ概要を確認します。
3. 一式置換のチェックを入れて復元します。既存の学習データと表示設定は置き換わります。必要なら先に現状も書き出してください。
4. 完了すると画面・テーマ・カード設定も更新されます。別のブラウザでも同じJSONを選べます。

書き出しは単一の読み取りトランザクションでスナップショットを取得するため、途中で別タブが更新しても内容が混ざりません。復元は全データ・表示設定を単一の書込トランザクションで置換します。確認後に別タブが学習内容または表示設定を更新すると、復元を拒否して再確認を求めます。

現在の形式は `stardia_backup` / `schemaVersion: 2`。v0.0.3以前の形式1も検証・変換して復元できます。ファイル上限は10MB。未対応形式・未知の項目・不正な値・重複ID・参照不整合は拒否します。完全復元では旧Study JSON・AI向けJSON・差分マージを扱いません。AI更新JSONはAI連携画面で取り込みます。新形式のJSONは旧バージョンのStardiaでは読み込めません。

JSONには暗号化していない学習内容が含まれます。保管先を選んで保存してください。ブラウザの保存領域が消去されても、手元に残したJSONから復元できます。端末間の自動同期はありません。

## v0.0.3からの移行

最初の起動でIndexedDBをversion 3へ更新します。旧タスクごとに学習項目と予定を1組作り、旧タスクIDは予定IDとして保持します。同名項目の自動統合や、記録との推測による関連付けはしません。

旧スナップショットはIndexedDB内の `migrationBackups` に退避し、件数・日時・予定時間・進捗・記録内容を検証してから、移行全体を確定します。失敗時はDBバージョンも含めて元の状態を保持します。新旧アプリを開いていた場合は古いタブを閉じ、新版で開き直してください。復元による一式置換・プロジェクト削除では、この退避データも対象範囲に応じて削除します。

## テスト

Node.js 22以上で `npm test`（単体テスト43件）。全確認は次のコマンドです。

```powershell
python -X utf8 -B scripts/verify.py
```

NodeがなければWindowsのVS Code同梱ランタイムを代替利用します。Chrome/Edgeがあれば、実際のIndexedDBで保存・競合・失敗・削除・移行・バックアップの往復を検証し、1440px / 390pxで画面操作を確認します。同じ専用プロファイルでChromeを終了・再起動し、保存内容も比較します。JSONを実際にダウンロードし、別の専用Chromeプロファイルへファイルから復元するテストも行います。ブラウザがない場合はSKIPと表示します。

テストは `.local/` の専用プロファイル、架空データ、ランダムなローカルポートを使用します。通常利用中のブラウザやStudyにはアクセスしません。テストDBの削除は専用テストプロファイル内だけで行います。**tests/browser.htmlを普段使いのStardiaのオリジンで開かないでください。** 検証サーバーとブラウザは終了時に停止します。スマートフォン実機検証とは異なります。

## 構成・開発方針

- `dist/`: ビルド不要の配信ソース。外部API・CDN・データ送信なし。
- `dist/src/domain/`: 日付・集計と共通の更新コマンド。
- `dist/src/storage/`: IndexedDB、デモ用メモリ、UI設定。
- `dist/src/ui/`: 画面描画・閲覧状態・AI差分・バックアップUI。
- `tests/`, `scripts/`: 自動テストと専用ブラウザ検証。
- `docs/`: 移植記録、保存設計、検証、開発バックログ。

単一プロジェクトUIから始め、保存キーはprojectIdで分離しています。将来は自由分類・階層・テンプレートを追加します。Studyのデータ・履歴・設定は共有しません。GitHub Pagesではdistだけを配置する想定です。この版ではremote設定の変更・Push・公開は行っていません。
